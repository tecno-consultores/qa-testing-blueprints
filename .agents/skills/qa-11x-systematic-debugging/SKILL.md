# QA 11X Systematic Debugging (`qa-11x-systematic-debugging`)

> **OUTPUT LANGUAGE & DYNAMIC MIRRORING:** Unless the target repository's `AGENTS.md` explicitly mandates a fixed output language, respond and explain reasoning in the **user's prompt language**, and write commit messages / human-facing documentation matching the **existing language of `README.md` and `CHANGELOG.md`** (explicitly ignoring `AGENTS.md` and `.agents/**`, which remain in concise English for token economy; default to the prompt language on empty repos).

Deterministic 4-phase root-cause troubleshooting protocol under Standard 11X (`qa-11x-architect`), enforcing **Rule Zero** ephemeral reproduction, AST knowledge graph tracing (`graphify-ast-navigator`), single-hypothesis experimentation with a 3-strike circuit breaker, and unmocked **RED-to-GREEN** regression locking.

## 1. The Iron Law of 11X Debugging

**ZERO SPECULATIVE CODE PATCHES WITHOUT PRIOR DETERMINISTIC ROOT-CAUSE ISOLATION.**

Modifying production code, tests, or configuration before reproducing the failure in Docker and tracing its exact fault boundary amplifies blast radius and creates silent QA escapes.

### Strictly Forbidden Debugging Anti-Patterns
1. **Shotgun Debugging:** Applying multiple unverified edits across files hoping one sticks.
2. **Swallowed Exceptions:** Wrapping failures in `try/except: pass`, bare `catch {}`, or fallback returns that mask real contract violations.
3. **Timing Bandaids:** Inserting arbitrary `sleep()` / `waitForTimeout()` calls instead of fixing deterministic synchronization, readiness probes, or state machines.
4. **Weakening Contracts:** Adding `# type: ignore`, `@ts-expect-error`, `as any`, lowering `--cov-fail-under=95`, relaxing assertions, or switching failing checks to hardcoded `'PASSED'`/`true`.
5. **Masking Persistence or Cross-Module Faults with Mocks:** Replacing failing SQL queries, migrations, `AsyncSession` transactions, or cross-module HTTP/store flows with mocks instead of fixing the underlying contract.

## 2. Phase 1 — Root Cause Investigation & Reproduction (Docker Rule Zero + AST)

Execute every step sequentially before proposing any fix:

1. **Ingest the Structured Failure Envelope (`Fail-Verbose`):**
   - Inspect `/tmp/qa-11x-last-failure.json` (generated by `certify_task_completion.sh` / `certify_11x_gate`) and stderr diagnostic excerpts to extract exact gate number, failing command, exit code, and sanitized stack trace.
2. **Reproduce Deterministically Inside Ephemeral Docker (`Rule Zero`):**
   - **NEVER** run tests, compilers, or linters on the host OS. Reproduce the exact failure inside `sinfallas/*` containers (`Makefile` targets or `run_ephemeral_qa`) with identical flags (`--import-mode=importlib`, `COVERAGE_FILE=/tmp/.coverage`, `mypy --strict --cache-dir=/tmp/mypy`, `HOME=/tmp`).
3. **Trace Impact with Graphify AST First (Before `grep` / `read_file`):**
   - Ensure `graphify-out/graph.json` exists (if missing, build it via `./scripts/actualizar-grafos-graphify.sh`).
   - Run `python3 .agents/scripts/inspect_blast_radius.py "<failing_symbol>"` (or MCP `inspect_ast_blast_radius`) and inspect `graphify-out/GRAPH_REPORT.md` to obtain exact declaring `file:line`, incoming callers (`⬅️`), and outgoing dependencies (`➡️`).
   - Read only targeted 40–80 line windows around the fault and its direct callers/callees.
4. **Backward Data-Flow Trace Across the 5 Classic 11X Failure Vectors:**
   - **(a) Post-Commit RLS Context Loss & `MissingGreenlet` (`QA-PG17-RLS`):** Did `await db.commit()` expire `SET LOCAL app.current_tenant_id` before a subsequent query or `write_audit_log()`? Verify `session.sync_session.info` + `@event.listens_for(AsyncSession.sync_session_class, "after_begin")` and explicit `await db.refresh()` or pre-commit primitive capture.
   - **(b) `JSON`/`JSONB` Serialization Escapes over `Decimal` / `UUID`:** Did `MockDbSession` omit strict `json.dumps()` validation without `default=str` while production `asyncpg` rejected `Decimal` (`Numeric(p, s)`), `UUID`, or `datetime`?
   - **(c) 3-Phase Temporal Lifecycle Boundaries:** Verify entity transitions across **Phase 1 Pending** ($t < t_0$, e.g. `t < starts_at`), **Phase 2 Active** ($t_0 \le t \le t_1$), and **Phase 3 Expired/Reverted** ($t > t_1$ or cancelled) — including Safe Mode rollbacks, pre-auth `TTL <= 300s`, and Step-Up leases.
   - **(d) Dual CLI/MCP `stdio` Interactive `TTY` Hangs (`QA-CLI-TTY-01`):** Does a dual CLI/MCP binary block forever waiting on `stdin` EOF instead of checking `isTTY`/`isatty()`, printing help, and exiting `0` within `<= 5s` when `--stdio` is absent?
   - **(e) Non-Root Container Bind-Mount `os error 13` (`Permission denied`):** Check host UID/GID alignment (`-u "$(id -u):$(id -g)"`), `COVERAGE_FILE=/tmp/.coverage`, `UV_CACHE_DIR=/tmp/uv-cache`, `HOME=/tmp`, `pnpm_config_store_dir=/pnpm/store`, and `pnpm-store-init` volume permissions (`chmod -R a+rwX /pnpm`).

## 3. Phase 2 — Differential & Contract Pattern Analysis

Before writing a hypothesis, compare the broken path against working invariants in the repository:

1. **Blueprint & Sibling Route Contrast:** Compare the failing implementation against canonical reference patterns in `fastapi/`, `vue3/`, `react-frontend/`, `node-backend/`, `php/`, `python/`, `bash-scripts/`, or `qa-11x-devsecops-hardener` (`references/stig_rls_vault.md`).
2. **Recent Change Isolation (`git` Diff & Archeology):**
   - Run `git status -s`, `git diff`, or `git log -S "<symbol>" -p -n 3` to pinpoint the exact commit or schema drift that introduced the regression.
3. **Deterministic Contract & Parity Validators (Ephemeral Container Execution):**
   Run the relevant repository governance validators in Docker (`sinfallas/base-python-uv:3.15`) to surface silent structural drift:
   - `python3 .agents/scripts/verify_alembic_orm_parity.py` — detects ORM vs. Alembic migration drift and `revision > 32` chars.
   - `python3 .agents/scripts/verify_no_orphan_api_endpoints.py` — detects mismatched or orphan frontend/backend API routes (`404`/`405`).
   - `python3 .agents/scripts/verify_topological_health.py` — detects circular dependencies and cross-layer AST violations.
   - `python3 .agents/scripts/verify_zero_orphan_vue_components.py` — verifies every UI view/component owns an active unit test.
   - `python3 .agents/scripts/verify_json_no_duplicate_keys.py` — catches silent shadowed i18n or config keys.

## 4. Phase 3 — Single-Hypothesis Scientific Testing & 3-Strike Escalation

Follow strict scientific isolation — never bundle multiple guesses into one edit:

1. **Formulate Exactly One Falsifiable Hypothesis:**
   > *"Failure `X` occurs at `file:line` because condition `Y` violates invariant `Z`; changing/logging `Y` will produce observed output `W`."*
2. **Minimum Diagnostic Probe:**
   - Apply the smallest reversible diagnostic assertion or targeted test run inside the ephemeral container to confirm or falsify the hypothesis.
   - **If falsified:** Revert the tentative edit immediately (`git checkout -- <file>`) before testing the next hypothesis. Never stack unverified patches.
3. **Mandatory Circuit Breaker — 3-Strike Architectural Escalation:**
   - Track consecutive failed hypotheses (`Strike 1 -> Strike 2 -> Strike 3`).
   - **HARD STOP AT STRIKE 3:** If **3 consecutive hypotheses fail**, **STOP editing code immediately**. Do NOT attempt a 4th speculative patch.
   - Escalate an architectural diagnosis packet containing:
     1. Exact Docker reproduction command and fail-verbose excerpt (`/tmp/qa-11x-last-failure.json`).
     2. Summary of the 3 refuted hypotheses and their observed outputs.
     3. AST blast-radius graph (`inspect_blast_radius.py` callers/callees) and suspected contract/architecture mismatch (e.g., cross-module state ownership, RLS session lifecycle, or missing spec invariant) for planning/operator review.

## 5. Phase 4 — RED-to-GREEN Regression Lock & QA-Escape Post-Mortem

Once the single root cause is proven:

1. **RED First (Unmocked Regression Test):**
   - Write or extend the failing regression test **before** applying the production fix.
   - Enforce **Anti-Mock Blindness & Anti-Silo Rules**: verify Module A mutation -> Module B `GET`/store propagation against the real DB/KeyDB engine without intermediate mocks, assert `write_audit_log` arguments and human-readable identities (zero raw UUID v4 strings), cover trimodal states (Virgin / Nominal / Degraded) or 3 clock phases when applicable, and include proportional Karate Labs `.feature` scenarios (injecting dynamic `Idempotency-Key` UUIDs) on `FULL_11X` API/UI flows.
   - Run the targeted test in Docker and confirm **RED** for the exact isolated root cause.
2. **Surgical GREEN Fix:**
   - Apply the minimal root-cause fix respecting `CC <= 5` (Grade A), strict static typing (`mypy --strict`, `vue-tsc --noEmit`, ESLint `--max-warnings 0`, PHPStan max), and `>= 95%` branch/line coverage.
   - Re-run the failing test and full stack QA suite in `sinfallas/*` containers until **100% GREEN** with zero warnings or skipped assertions.
3. **AST Refresh, 10/10 Certification & QA-Escape Post-Mortem:**
   - Refresh AST graphs incrementally: `./scripts/actualizar-grafos-graphify.sh`.
   - Sync documentation/`CHANGELOG.md` and `.agents/ACTIVE_TASK.md` (`<= 40` lines), run `make sync-governance` and `make certify` (`10/10` gates), and stop at a local `git commit` (`QA-GIT-GATE-01` — no `git push`).
   - **QA-Escape Learning Loop:** Whenever the bug escaped prior tests into UAT or production, proactively emit `💡 Oportunidad de Mejora Detectada para el Estándar QA 11X` explaining which blind spot failed and invoke `propose_skill_evolution_pr` (or update `.agents/` + `docs/` + `security-auditor.ts` in this blueprint repository) so the escape class can never recur.
